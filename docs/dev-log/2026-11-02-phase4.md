# 2026-11-02 실습 기록: 한국투자증권 실계좌 연동 (Phase 4)

InvestLab에 한국투자증권(KIS) Open API를 조회 전용으로 연결하고, 실제 계좌로 확인하기까지의 과정을 정리했습니다. 계좌번호, 보유 종목, 금액, 키 값은 이 문서에 적지 않습니다.

## 1. 출발점

- Phase 1~3 완료 상태: Mock 데이터 분석, Supabase 로그인과 RLS, 소유자 전용 LIVE 인가
- 사용자가 `.env`에 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT_NO`를 직접 입력했고, 형식 점검(길이, `8자리-2자리`, 상품코드)을 통과한 상태에서 시작했습니다.

## 3. 확인하며 발견한 것

### 해외 수량은 `cblc_qty13`이 아니라 `ccld_qty_smtl1`

해외 체결기준현재잔고(`CTRP6504R`)의 `cblc_qty13`(잔고수량)에는 **당일 매수분이 빠져** 있었습니다. 평가금액(`frcr_evlu_amt2`)과 매입금액(`frcr_pchs_amt`)은 체결수량합계(`ccld_qty_smtl1`) 기준이었습니다. 처음 필드를 그대로 썼다면 오늘 산 종목의 수량이 절반으로 나왔을 것입니다. 교차 검증(비율만 출력)으로 잡았습니다.

### 해외 ETF는 API로 구분되지 않음

해외 상품기본정보(`CTPF1702R`)의 구분 코드는 VOO, QQQ 같은 ETF도 일반 주식과 같은 `01`로 줍니다. 공식 종목 마스터 파일의 증권 유형(`3` = ETP, 구분코드 `001` = ETF)을 하루 한 번 받아 판별합니다. 국내는 상품기본조회(`CTPF1002R`)의 `scty_grp_id_cd`(`ST` 주권, `EF` ETF)로 구분됩니다.

### 로그에 계좌번호가 남을 뻔함

테스트에서 `httpx` 라이브러리가 INFO 로그에 요청 URL 전체(`?CANO=…`)를 남기는 것을 발견했습니다. 기존 마스킹은 `8자리-2자리` 형태만 가렸기 때문에 놓쳤습니다. `httpx` 로그를 WARNING 이상으로 올리고, `CANO=`·`ACNT_PRDT_CD=` 패턴도 가리도록 고쳤습니다.

### 토큰 재발급 제한과 알림톡

토큰은 1일 유효하고 재발급은 1분에 1회로 제한되며, 발급할 때마다 알림톡이 갑니다. 서버를 `--reload`로 띄우면 코드를 고칠 때마다 재시작되므로, 토큰을 파일에 캐시해 재시작 때도 재사용하게 했습니다.

## 4. 구현 요약

- `apps/api/app/integrations/kis/client.py`: 토큰 발급·캐시, 조회 경로 허용 목록(주문 경로 호출 불가), 호출 간격, `EGW00201` 재시도, 만료 토큰 1회 재발급, 연속 조회
- `apps/api/app/integrations/kis/parse.py`: 국내·해외 잔고 응답 해석. 필수 필드가 없으면 응답 전체를 쓰지 않음
- `apps/api/app/integrations/kis/master.py`: 공식 해외 종목 마스터로 ETF 판별
- `apps/api/app/integrations/kis/classification.py`: KIS가 주지 않는 분류(ETF 유형, 섹터, 추종 지수)를 사용자가 지정하는 파일(`data/live/classifications.json`, 커밋 제외)
- `apps/api/app/providers/kis.py`: LIVE Provider. 국내·해외 중 하나라도 실패하면 전체 오류, Mock 대체 없음, 30초 결과 공유
- LIVE 이력: KIS는 과거 평가금액을 주지 않으므로, 소유자가 저장한 스냅샷으로 대시보드 차트를 그림

자세한 매핑과 오류 코드는 [KIS 연동 문서](../kis-integration.md)에 있습니다.

## 5. 로그인 비밀번호 재설정 과정

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 로그인 비밀번호를 모름 | 계정을 대시보드에서 만들 때 정한 값. Supabase는 암호화된 값만 저장 | 재설정 필요 |
| 재설정 메일 링크가 `localhost`로 열림 | 링크는 Site URL(`localhost:3000`)로 오는데, 앱에 새 비밀번호 화면이 없었음 | `/reset-password` 화면 추가. 첫 화면으로 온 재설정 링크를 자동으로 넘기고, 주소창의 토큰은 바로 지움 |
| `email rate limit exceeded` | Supabase 기본 메일 서비스의 시간당 발송 한도 | SQL Editor에서 사용자가 직접 비밀번호를 갱신 |

배운 점

- 로그인 아이디는 **이메일**이고, UID는 서버가 소유자를 확인하는 데만 씁니다.
- SQL Editor의 `UPDATE`는 성공해도 "No rows returned"로 표시됩니다. 실제 반영 여부는 `updated_at`으로 확인했습니다.
- SQL Editor는 실행한 쿼리를 기록에 남기므로, 비밀번호가 들어간 쿼리는 실행 후 기록에서 지워야 합니다.

## 6. 비밀 값 관리

- `.env`, `apps/web/.env.local`, `.cache/`(토큰·마스터 캐시), `data/live/classifications.json`은 `.gitignore` 대상입니다.
- 커밋 전에 실제 App Key, App Secret, 계좌번호(형식 3가지), 토큰, 키 앞부분 16자로 과거 커밋, 커밋 메시지, 커밋 대상 파일을 검색했고 모두 0건이었습니다. 값은 출력하지 않았습니다.
- KIS 확인 스크립트는 필드 이름, 값 형태, 비율, 건수만 출력하고, 예외 메시지도 출력하지 않습니다.
- 응답과 오류에는 KIS 오류 코드(`msg_cd`)만 싣고, 계좌번호가 들어갈 수 있는 원문 메시지(`msg1`)는 싣지 않습니다.

## 7. 서버 실행과 종료

```bash
# 실행
cd apps/api && .venv/bin/uvicorn app.main:app --reload --port 8000
cd apps/web && npm run dev

# 종료: 각 터미널에서 Ctrl + C
# 터미널을 찾기 어려우면
kill $(lsof -tiTCP:3000 -sTCP:LISTEN)
kill $(lsof -tiTCP:8000 -sTCP:LISTEN)
```

서버를 꺼도 KIS 토큰은 `.cache/`에 남아 하루 동안 재사용됩니다.
